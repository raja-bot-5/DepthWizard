# Building and object heights: confidence and shadows (Phase 11 T5)

Generated by `experiments/11_confidence/make_t5_report.py` from `runs/exp11_confidence/20260929T154725Z`, `runs/exp11_shadows/20260929T154247Z` and `runs/buildings/20260929T153353Z`.

*Height above ground* = DSM − an estimated local ground. It is **derived, not measured**. The truth used here is LiDAR DSM − DTM from the same 2013 survey, so the datum cancels. Scores are on held-out test blocks only.

## 1. Confidence levels

Each derived height gets **low** or **medium**. It is low if any of these apply: no visible ground within the 60 m window; ESA WorldCover tree cover; water; or height < 2 × the DSM's 1-σ uncertainty. **There is no *high* level:** no derived height has been validated to that standard.

**What the levels do and do not tell you:**

- They flag real failure regimes. Forest is almost entirely low (canopy hides the ground). Water is flagged (both the estimate and the LiDAR DTM are unreliable there). *Height below 2σ* on cells where LiDAR sees an object marks **missed objects**, with some of the largest errors.
- **Medium does not mean accurate.** Pooled over object cells, medium is only slightly better than low (RMSE 4.40 vs 4.70 m). At the urban site the order reverses (buildings: low 4.40, medium 4.92 m). Every derived height carries a 2–4 m underestimate, because the model detail is scaled by one factor fitted at 30 m. No per-pixel flag can see that. The API and UI therefore show the measured error for each level next to the level itself (`height_confidence_evidence.json`).

## 2. Shadow-based building heights (prototype)

height = shadow length × tan(sun elevation). The shadow runs from the OSM footprint edge along the anti-sun direction; the 75th percentile of runs is used.

| | value |
|---|---|
| NAIP STAC time | 2021-07-26T16:00:00+00:00 (a round hour: possibly nominal, UNKNOWN) → sun az 103.2°, el 44.93° |
| Shadow direction measured from the image | sun az 109.0° → solved 2021-07-26T16:27:00+00:00, el 49.89° (peak contrast 1.82) |
| Shadow mask | 3-class Otsu darkest class minus vegetation, 8.8 % of the scene. Chosen by a label-free criterion (azimuth-peak contrast), not by LiDAR. Other detectors gave sun azimuths of 94–109°. |

| shadow, nominal 16:00Z sun | 97/168 | -3.77 | 5.58 | 0.14 | 5.58 / 0.14 |

| shadow where clean, else c2 | 168/168 | -3.39 | 5.00 | 0.20 | 5.43 / 0.08 |

**Decision: shadows are NOT used for calibration.** None of the shadow variants beats the current method on held-out buildings, which was the condition for using them. Shadow length barely tracks LiDAR height (r ≈ 0.1). The visible causes:
- NAIP is orthorectified to terrain, not true-ortho. Roofs lean over and hide part of their own shadows. The detected shadows are 1–5 px slivers, where 7–14 px are expected.
- OSM outlines follow roofs, not wall bases.
- Much of the dark area is courtyards and roof structure inside footprints.
- Buildings here are mostly 3–8 m tall, only a few pixels of shadow. LiDAR is from 2013, the image from 2021.
The module (`calibration/shadows.py`, with 6 tests) stays as a prototype. THIS SHOULD BE TESTED on Cartosat-2S, whose metadata carries sun angles and whose viewing geometry is known.
