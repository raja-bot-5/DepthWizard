# Does the score depend on the reference DEM? (Phase 11 T2)

Source: `runs/exp11_reference/20260929T150207Z/metrics.json`, generated by `experiments/11_reference_choice/make_reference_md.py`. Same three NAIP 0.6 m sites as `docs/results.md`.

The FAQ says GeoTIFF output is scored against "an absolute DSM such as SRTM or Copernicus". We don't know which one, or at what resolution. So the **real pipeline** was run twice per site: calibrated to Copernicus GLO-30, and calibrated to SRTM (NASADEM). Both products were then scored against every candidate reference, and against the independent LiDAR DSM.

## Setup

| | |
|---|---|
| Products | (a) = the calibration DEM, bilinear on the image grid (`dem.tif`); (c2) = pipeline default `dsm.tif` (DA3-Mono-Large, smooth residual) |
| References | Copernicus GLO-30 (EGM2008); **SRTM = NASADEM HGT v001** (EGM96 → EGM2008); Tilezen skadi (EGM96 → EGM2008; **over the USA it is 3DEP/NED-derived bare earth, not SRTM**); USGS 3DEP LiDAR DSM 2 m (NAVD88 → EGM2008) |
| Pixels scored | Held-out test blocks only (the pipeline's own 154 m checkerboard; fit blocks excluded) |
| 30 m | Product area-averaged onto the reference's native 1″ grid; a cell counts if it is fully inside the image and ≥ 90 % test pixels |
| 0.6 m* | **Reference bilinear-upsampled to the 0.6 m image grid** and compared pixel by pixel. This does not add real detail to the reference. It is how a scorer might compare a 0.6 m DSM to a 30 m DEM |
| Datums | Everything converted to EGM2008 with PROJ grids before comparison |

## Findings

1. **The reference choice dominates the score.** The same default file scores 0.25–0.93 m RMSE against Copernicus at 30 m, and 2.5–4.3 m against SRTM: 3 to 10 times worse. Every method difference we can measure is under 1 m.
2. **Calibrate to the scorer's DEM.** Using the other DEM costs +1.9 to +3.7 m RMSE at 30 m. If the organisers name the DEM, the pipeline switch (`dem_source`) is the single most valuable setting.
3. **Against real terrain (LiDAR), Copernicus is clearly better:** 3.24 / 4.38 / 2.13 m vs 4.34 / 6.59 / 3.67 m when calibrated to SRTM. Copernicus stays the default. SRTM (NASADEM, epoch 2000) is older and noisier than Copernicus (TanDEM-X, 2011–2015).
4. **At 30 m, the model detail costs almost nothing** (−0.01 to +0.38 m against the calibration DEM). **At 0.6 m against a bilinear-upsampled DEM, any real detail is penalised** (+2.0 to +2.2 m where there are buildings or trees), even though it improves accuracy against LiDAR. A scorer that upsamples SRTM/Copernicus to 0.6 m would rank a blurred DEM above a better DSM. This is a question for the organisers.
5. **Resampling floor:** the DEM scored against itself after bilinear-to-0.6 m and back to 30 m still shows 0.25–0.87 m RMSE (largest in steep terrain). No product can score 0 at 30 m.
6. **Tilezen skadi is not SRTM in the USA.** It sits 5.5 m below Copernicus in forest because it is 3DEP bare earth. It is not a valid stand-in for an SRTM judge on these sites. Over India, skadi's source is SRTM per the Tilezen docs (UNKNOWN — NEEDS VERIFICATION per tile).

## Limitations

- Three US sites (NAIP, Boulder). Copernicus − SRTM differences over India, and in Cartosat scenes, will differ.
- NASADEM is one SRTM product. CGIAR SRTM v4 and USGS SRTMGL1 are close relatives but not identical. The organisers' exact SRTM product is UNKNOWN.
- One seed, one model (DA3-Mono-Large). Test blocks only.
